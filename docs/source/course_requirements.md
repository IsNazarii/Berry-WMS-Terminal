## Загальні технічні вимоги
* **Мова:** Для реалізації використовується C++ або інша сучасна об'єктно-орієнтована мова.
* **Структура:** Кожне завдання реалізується як одна програма з однією точкою входу (`main()`).
* **Контроль версій:** Обов'язкове використання систем контролю версій (наприклад, Git) із регулярними проміжними комітами та змістовними коментарями.
* **Тестування:** Написання Unit-тестів є обов'язковою вимогою для отримання оцінки "відмінно" (90+ балів) у першому семестрі.
* **Використання ШІ (LLM):** Використання ChatGPT та аналогів дозволене, але потребує чіткої вказівки. Студент повинен зберегти історію запитів, повністю розуміти згенерований код і нести відповідальність за наявні в ньому помилки.

## Лабораторна робота №1: Базові ідеї ООП
Завдання можна виконати через власний навчальний проєкт (найкращий варіант), участь у "великих проєктах", розробку прикладів коду або за стандартизованими варіантами. 

**Вимоги до коду:**
* Мінімум **9 класів** або аналогічних типів.
* Мінімум **15 полів** у сумі по всіх реалізованих класах.
* Мінімум **25 нетривіальних методів** (конструктори, звичайні геттери та сеттери не враховуються).
* Мінімум **2 ієрархії успадкування** (принаймні одна з ієрархій повинна містити не менше 3 класів).
* Мінімум **3 незалежні випадки поліморфізму** (щонайменше 1 статичний, наприклад templates, та 1 динамічний, наприклад віртуальні методи).
* Правильна інкапсуляція з доцільними рівнями доступу.

## Лабораторна робота №2: Графічний інтерфейс (GUI)
Дозволяється використання будь-якої технології для створення desktop, web або mobile інтерфейсів. 

**Основні вимоги:**
* Логіка програми має бути чітко відділена від коду графічного інтерфейсу.
* Мінімум **4 вікна**, екрани або форми.
* Мінімум **20 елементів керування** сумарно.
* Мінімум **1 елемент-контейнер** (таблиця, список, дерево тощо).
* Мінімум **10 обробників подій**.

## Лабораторна робота №3: Використання зовнішніх бібліотек
* Необхідно задіяти зовнішню бібліотеку або фреймворк для розширення функціоналу.
* **Обмеження:** Заборонено використовувати частини стандартної бібліотеки мови або інструменти, що вже розглядалися в межах курсу (наприклад, Qt, Catch2, GoogleTest).
* У репозиторії слід явно вказати використані бібліотеки та їх задіяні можливості.
* **Звіт-ретроспектива:** Для отримання максимального балу обов'язково треба написати звіт. Він має містити аргументовані відповіді на питання щодо доцільності вибору бібліотеки, складності її налаштування та загального досвіду використання (включаючи посилання на використані ресурси).

## Навчальний проєкт
* Проєкт розробляється паралельно з лабораторними роботами самостійно або в команді.
* Завдання здається у три етапи: 1) вибір теми, 2) альфа-версія, 3) фінальний реліз.
* Тема має бути оригінальною і пропонувати нові або покращені можливості порівняно з існуючими аналогами.
* **Аналіз конкурентів:** Для претендентів на оцінку "відмінно" обов'язковою вимогою є проведення аналізу існуючих аналогів із зазначенням відмінностей та переваг розроблюваного продукту.
